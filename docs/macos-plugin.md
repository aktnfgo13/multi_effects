# macOS AU / VST3 v0.6

The plugin wraps the existing v0.5 stereo Core without modifying DSP algorithms.
Standalone remains a separate target with its existing device/routing/settings UI.
This is a functional plugin prototype, not a signed/notarized distribution.

## Build and bundles

```sh
cmake -S cpp -B cpp/build -DCMAKE_BUILD_TYPE=Release \
  -DMULTI_EFFECTS_BUILD_APP=ON -DMULTI_EFFECTS_BUILD_PLUGIN=ON
cmake --build cpp/build --parallel 4
ctest --test-dir cpp/build --output-on-failure
```

Artifacts under `cpp/build/app/plugin/MultiEffectsPlugin_artefacts/Release/`:

- `AU/Multi Effects.component`
- `VST3/Multi Effects.vst3` (including `Contents/Resources/moduleinfo.json`)

JUCE remains pinned by the existing app CMake. Plugins are opt-in and macOS-only.
Set both BUILD options OFF for Core-only (no JUCE download); set APP ON and PLUGIN
OFF for Standalone-only. PLUGIN ON with APP OFF is also supported. Offline reuse:
`-DFETCHCONTENT_SOURCE_DIR_JUCE=/absolute/path/to/existing/juce-src`.
No automatic global installation, installer, distribution signing or notarization.

The validation copy of the AU is user-local:
`~/Library/Audio/Plug-Ins/Components/Multi Effects.component`.
The VST3 stays in the build directory; if needed, copy it to the user's
`~/Library/Audio/Plug-Ins/VST3/` folder. Do not replace an existing unrelated bundle.
AU validation: `auval -v aufx Mfx6 Mefx`. Manufacturer `Mefx`, subtype `Mfx6`, type
`aufx`; VST3 IDs are generated by JUCE from the same stable plugin identity. Keep
these identifiers stable for existing DAW projects.

## Adapter and automation contract

`Processor` owns a fixed APVTS host parameter bank created once. Host IDs use
`<effect-type>.<existing-parameter-id>` plus `<effect-type>.bypass`; the global bypass
is `plugin.bypass`. All registry types have fixed entries, even when absent from the
current chain. A bank controls the **first instance of that effect type** in chain
order. Extra instances retain their preset values; missing instances make their bank
inactive. Instance IDs, order and unknown-to-the-bank additional instances are not
renamed or removed. The editor intentionally does not add/remove/reorder instances;
load a Standalone preset to change graph structure. Host parameters never change count
or identity after construction. Future slot automation should add explicitly versioned
slot IDs rather than reinterpret existing banks or reorder AU parameter version hints.

The functional editor uses JUCE's generic host parameter controls, so both GUI edits
and DAW automation reach the same APVTS atomic targets. It adds chain order, preset
load/save, Cabinet WAV import, aggregate input/output peak/CLIP and latency. There are
no audio-device controls. Controls for absent effects remain visible but have no DSP
binding. Continuous parameters are sampled per host block and use existing Core
smoothing; this is not sample-accurate automation.

Supported host buses: mono input to stereo output and stereo input to stereo output.
Mono input is copied into R before the existing stereo chain, preserving center until
spatial effects. Rate/block size is passed through prepare; oversized and irregular
callbacks are chunked through preallocated dry-alignment scratch. Stereo Core lane
state, oversamplers and Cabinet histories are unchanged. The plugin does **not** add
Standalone's -6 dB output gain, mute or final hard clamp: finite headroom is retained
and CLIP indicates samples at/above 0 dBFS. Compare with matching output gain when
A/B testing against Standalone. Non-finite input/output is replaced with zero.

## Configuration ownership and latency

Host prepare/release/destruction must be serialized against processing, as required
by AudioProcessor lifecycle. `prepareToPlay` builds the initial stereo render state;
`releaseResources` retires it while stopped. A control mutex protects configuration
snapshots, JSON and off-thread builds, never audio processing.

Discrete oversampling changes increment an atomic revision. A worker polls at 10 ms,
clones the configuration, captures current targets and prepares the replacement.
An atomic mailbox publishes it. The audio thread adopts at a block boundary and
hands the old pointer to a one-entry retirement mailbox; only the worker destroys
retired states. A full retirement mailbox defers adoption rather than freeing or
waiting in audio. Pending revisions are coalesced; failed builds keep the active
state and an editor-visible error. State/IR loads use the same path. All buffers,
function captures and bindings are allocated during prepare/build, not process.

Rebuilds reset tails and can cause a discontinuity. Oversampling automation is
**deferred**, not sample-accurate or seamless; rapidly automated/offline mode changes
can depend on worker scheduling. For deterministic offline export, select the mode
before host prepare/render and keep it fixed. Continuous automation does not rebuild.

Latency is the sum across effects, not channels: default chain 128 samples at 1x;
320 when both Amp and Distortion use 2x/4x. Audio publishes the adopted latency as an
atomic; the worker requests a message-thread AsyncUpdater which calls
`setLatencySamples`. No host notification/allocation occurs in processBlock. Host PDC
response is asynchronous and host-dependent; stop playback for mode/graph changes
when phase continuity matters. No claim of click-free PDC transitions is made.

Global host/parameter bypass uses a smoothed, latency-aligned stereo dry path, with
fixed maximum history capacity for 24 effects. DSP continues to run so tails/state
remain valid. Per-effect bypass uses the existing Core behavior. There is no plugin
DSP Mute. Tail reporting uses a conservative 300 seconds for the default chain;
extreme custom chains with many serial delays may exceed this estimate.

## Preset / project state

`PresetIO::deserializePreset(var)` is extracted from the existing file loader;
Standalone and plugin use the same v2/v3 validation and serialization. Host state is
an in-memory JSON envelope with `plugin_state: 1`, `preset`, `bypass`, `preset_name`.
It contains all effect identities/order/bypass/targets and embedded IR samples/rate/name.
No original IR file is needed after project restore. Input/output devices, Standalone
routing/mute and buffer preferences are never serialized into plugin state. State
input is bounded to 64 MiB and malformed data retains the previous configuration.

State get/set and preset/IR operations are non-realtime services; the DAW must not call
these heavyweight operations from processBlock. Host notifications during install
are made without the control mutex, allowing host reentry. Concurrent installs are
rejected instead of interleaving. Extra absent-effect bank values are not a separate
preset concept; only bindings represented by the restored chain are reconstructed.

## Validation and performance

`PluginLifecycleState` simulates both host input layouts at 44.1/48/96 kHz and 1x/2x/4x,
compares adapter output with direct Core, exercises 64/128/256/512/7/1001 frames,
release/reprepare, NaN/Inf, stable automation mapping for legacy instance IDs,
project state/order/embedded IR, malformed state retention, v2 import, global/host
bypass and deferred latency. `PluginConcurrentControls` overlaps automation, state
snapshots, worker rebuilds and processing. AllocationTracker covers processing in
Release; sanitizers use their native allocator.

Run `cpp/build/app/plugin/test_plugin profile`. 48k/128 stereo, 100 warmup + 2000
measured blocks; direct Core and adapter timings are interleaved on this Mac:

| Factor | Core mean/max us | Adapter mean/max us | Adapter max/deadline |
|---|---:|---:|---:|
| 1x | 32.30 / 67.71 | 33.04 / 56.83 | 2.13% |
| 2x | 174.42 / 230.92 | 175.40 / 227.25 | 8.52% |
| 4x | 324.55 / 2293.21 | 324.77 / 2151.21 | 80.67% |

Mean wrapper overhead was about 0.2–1.0 us. Both paths had scheduler outliers at 4x;
observed maximum is not a guaranteed execution bound. Deadline: 2666.67 us. This does
not measure a DAW's entire graph or predict external/hardware performance. Logs/CSV
are ignored `cpp/build/v06-*` files.

AU build and `auval` passed including mono-to-stereo, host parameter/ramp scheduling,
multiple rates and unusual/max block sizes. VST3 binary and module manifest were
built; no standalone VST3 validator was found, and none was installed. Logic exists,
but UI automation timed out after its startup/project chooser, so Logic plugin
manager discovery and audible DAW rendering are not claimed verified. No existing
Logic project was opened or modified.

Final v0.6 regression: Release CTest 25/25, pytest 42/42 and all six existing
Python/C++ comparison scripts passed. ASan/UBSan passed 23/23 tests (long-run tests
excluded, ASan leak detection disabled); TSan passed all six concurrency tests.
Standalone Debug/Release, Core-only and AU/VST3 Release builds succeeded. The
Release Standalone launched with advancing callbacks at 48 kHz / 128 frames using
output-only built-in speakers, muted; external input monitoring was not tested.
The final user-local AU copy passed `auval`. Detailed logs are `cpp/build/v06-*`.
